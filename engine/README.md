# CueClock 引擎核心

不带界面的调度与 UDP 收发核心。后续界面（Electron）只作为它的客户端。

需要 Node ≥ 22.18（直接运行 `.ts`，无需编译）。

```bash
cd engine && npm install
npm test                                                   # 130 个测试
npm run typecheck
node src/cli.ts check    data/sample-project.json          # 项目静态检查
node src/cli.ts simulate data/sample-project.json --from 2026-09-26 --days 3   # 模拟（不发包）
node src/cli.ts run      data/sample-project.json --log-dir ./logs             # 真实运行，--dry 则不发包
node src/cli.ts init     my-project.json                   # 新建空项目
node src/cli.ts daemon   my-project.json                   # 启动引擎守护进程（默认端口 47800）
node src/cli.ts ctl status                                 # 另开终端：连接守护进程查询状态
node src/cli.ts ctl watch                                  # 实时查看日志
node bench/jitter.ts 200 6                                 # 毫秒抖动实测
```

## 模块

| 文件 | 作用 |
|---|---|
| `types.ts` | 项目数据模型（项目文件 = 这个结构的 JSON） |
| `payload.ts` / `match.ts` | ASCII 转义、HEX 解析；精确/前缀/包含/正则匹配（回包和触发器共用） |
| `calendar.ts` / `rules.ts` | 日子类型（节假日/调休上班/周末/工作日）、生效规则、组内互斥与优先级 |
| `plan.ts` | 把某一天展开成按毫秒排序的执行点（偏移、延时、重复） |
| `clock.ts` / `scheduler.ts` | 真实时钟（分段等待+末端轮询）与虚拟时钟；逐日调度 |
| `udp.ts` | 常驻发送套接字（可绑定固定本地端口）、回包等待、监听端口、模拟传输 |
| `triggers.ts` | 触发器：来源白名单 → 口令 → 匹配 → 防抖 → 频率限制 → 二次确认 |
| `recovery.ts` | 断电重启后的状态恢复 |
| `engine.ts` | 把以上串起来；产生日志事件；热更新项目；急停、手动执行、测试发送、状态查询 |
| `daemon.ts` / `client.ts` / `protocol.ts` | 引擎守护进程与客户端（见下节） |
| `store.ts` | 项目文件原子保存 + 自动备份 |
| `network.ts` | 本机网卡枚举、机器级网络设置校验、按目标子网选发送网卡（`chooseLocal`） |
| `commands.ts` | UDP 指令库：`{{参数}}` 代入、把「引用指令」的动作展开成可发送的 UDP 动作 |
| `calendarText.ts` / `simulate.ts` | 节假日日历文本导入导出；多天模拟视图（界面的预览和 CLI 共用） |
| `validate.ts` | 运行前静态检查（引用、HEX、正则、日期、端口…） |

## 引擎 ⇄ 界面（daemon）

引擎作为独立进程运行，界面（以后还有网页）只是客户端：界面关闭、崩溃、重启都不影响调度。

- 通信：`127.0.0.1` 上的 TCP，每行一个 JSON。第一条必须是带令牌的 `hello`，否则断开。
- 发现：daemon 启动后把端口和随机令牌写进状态目录的 `daemon.json`（权限 0600，退出时清理）。
  状态目录：Mac `~/Library/Application Support/CueClock`，Windows `%APPDATA%\CueClock`，可用 `CUECLOCK_HOME` 覆盖。
- 方法：`status` `getProject` `saveProject` `validateProject` `getLogs` `pause` `resume` `testSend` `runCue` `simulate` `ping` `getSettings` `openProject` `newProject` `shutdown`。
  推送事件：`log`、`status`、`project-changed`。网络：`getNetwork`（含本机网卡列表）、`setNetwork`、`listInterfaces`；`runCommand`（立即执行一条指令，可以是未保存的草稿）。
- 保存项目带版本号 `baseRev`，别的客户端改过则返回 `conflict`；校验不通过则不落盘；通过后原子写入并备份旧版本（保留最近 30 份），引擎热更新。
- 项目文件有错误时 daemon 仍会启动（引擎不运行），等界面保存出一份合法项目后自动启动引擎。
- 客户端 `DaemonClient` 支持断线自动重连，并在每次重连前重新读取 `daemon.json`（引擎重启后端口和令牌会变）。
- 切换项目（`openProject`/`newProject`）：先停当前引擎再启动新的；版本号只增不减，其他客户端手里旧项目的草稿再保存必被拒；目标有错误默认拒绝（`force` 才打开）；新建绝不覆盖已有文件；项目文件必须是绝对路径。引擎在状态目录的 `settings.json` 里记住上次项目和最近 8 个。
- 网络设置是机器级的（`settings.json` 的 `network`），优先于项目里的旧 `settings.localAddress`。发送套接字绑定失败（网卡不存在/端口被占）时引擎不运行，并按 `retryMs`（默认 5 秒）重试直到成功；`setNetwork` 会重启引擎。
- 急停：暂停期间到点的事件、收到的触发、启动时的断电恢复都不执行并写日志；手动测试发送、手动执行事件点不受影响；恢复后不补发。**急停状态持久化**在 `settings.json`，引擎/daemon 重启后仍保持，需手动恢复。

## 指令库与多网卡（数据模型要点）

- **指令（`commands`）**：目标（设备/标签）、**端口**、格式、内容、结束符、回包、重复、断电恢复、发送网卡，配一次、到处用。内容里写 `{{名字}}`，在 `params` 里声明（可带默认值）。
- **动作**有两种发送方式：`command`（引用指令，只填参数值，可覆盖偏移/目标/端口）和 `udp`（自定义，所有字段自己填）。展开发生在排日程、断电恢复、触发器执行、手动执行时，**之后引擎只看到普通 UDP 动作**。
- **端口优先级**：动作覆盖 > 指令 > 设备默认端口。设备的 `port` 现在可不填；所有会发送的目标都必须能得到一个端口，否则校验报错。
- **多网卡**：`network.localAddresses` 可多选，每块网卡一个发送套接字；发给某目标时按**目标所在子网**选网卡（多块匹配取前缀最长），`255.255.255.255` 每块各发一次，没有匹配的用第一块，指令里可用 `sendFrom` 强制指定。部分网卡缺失时用其余的先跑，缺失的后台重试；全部缺失才算失败。
  限制：绑定网卡 IP 只决定包的**源地址**；发往所有已选子网之外的目标时，实际出口由系统路由表决定。
- 旧项目文件兼容：单个 `settings.localAddress`、没有 `commands` 的项目照常运行。

## 稳健性（常驻运行必须扛得住的事）

- **调度循环不会静悄悄死掉**：某天的日程排不出来（数据异常）或循环内出现意外，会上报并按间隔重试，之后照常执行；进程级的未处理异常/拒绝只记录、不退出。
- **停止即停止**：引擎停止/切换项目时，触发器、恢复、手动执行里还在「延时等待」的动作会被取消，已停止的引擎不再产生日志。
- **休眠唤醒/系统时间大幅前跳**：错过的一批事件只记一条汇总，并自动补发各时间线的「当前应有状态」（标了重启后补发的动作）。
- **回包只确认一个请求**：同一设备同时有多个请求等回包时，一个回包只交给最早且接受它的那个。
- **触发端口防刷屏**：不匹配/被拒/被忽略的包每秒最多逐条记 50 条，超出的在下一秒补一条汇总；触发了的、等待二次确认的包永远逐条记。
- **热更新保留状态**：保存项目不会丢掉触发器的防抖和二次确认等待。
- **磁盘**：按天日志保留 30 天（启动时和每 6 小时清理）；项目备份至少间隔 60 秒才新增一份，避免连续自动保存把历史备份挤光。
- 校验新增：同一时间线内事件点 id 重复；参数名可用中文。

## 实现时定下的语义（构思文档没写细的地方）

- **规则条件**：`weekdays / dateRanges / dates / dayKinds` 满足任意一个即命中，`excludeDates` 永远优先。
- **互斥组**：只运行优先级数字最小的一条；同优先级取项目里靠前的。
- **开了回包校验的动作不再按 `repeat` 重复**，重发由 `retries` 负责，避免一次动作被校验多次。
- **ASCII 比较忽略数据末尾的 `\r\n`**（设备常带换行）；`pattern` 自己以 `\r`/`\n` 结尾时才精确比较。HEX 不忽略。
- **回包来源必须等于目标 `ip:port`**；回包按"任一包匹配即确认"，超时仍无匹配时有回包则报"回包不符"，无回包报"超时"。
- **调度器启动**按动作的实际执行时刻接续所有尚未到点的动作，包含已开始事件中的 offset、delay 和剩余 repeat；恰好到点的动作归调度器。恢复只选严格早于启动时刻的状态，两边不会重复。
- **断电恢复**：同一生效模式内，每个设备分别选取最近已发送动作所属的事件点，只补发该事件中 `chase: true` 的动作；标签会裁剪到仍需恢复的设备，避免其他目标的较晚事件遮掉旧状态。该设备最新事件不补发时，不重放旧事件。尚未到点的延时动作不覆盖旧状态；累计延时和重复次数只展开一次。整体恢复默认延迟 3 秒。
- **迟到超过 `maxLateMs`（默认 5 秒）的事件不补执行**，记为 `missed`。电脑休眠唤醒后不会把一堆旧指令一起发出去。
- **时间线控制动作**（临时禁用/启用）默认一直有效，直到再次启用或引擎重启；禁用动作可选 `until: 'midnight'`，到本地午夜自动恢复。
- 时间按**本机时区**的墙上时间计算；未处理夏令时（中国无夏令时）。仅支持 IPv4。

## 实测（Mac，本机回环，空闲）

`bench/jitter.ts`：3 轮 × 200 个随机毫秒点，计划时刻 → 设备收到时刻，误差最大 1ms，中位 0ms。
这只证明调度本身；真实网络延迟另算，Windows 尚未测试，机器高负载时会变差。

## 日程模式与目标轨道的兼容字段

数据仍采用原有 `timelines → cues → actions`：一个 Timeline 是日程模式，目标轨道由动作的目标、指令覆盖目标和设备标签推导，不另外存一份日程。`Timeline.color`、`Device.color` 是界面颜色；`Cue.defaultTarget` 仅预填新动作的目标，实际发送仍以动作 targets 为准。旧项目不需要这些字段。

2026-10-06 新增恢复回归测试：多目标独立恢复、标签裁剪、不补发状态、延时尚未到点、重复不被再次展开；并修正禁用模式参与同优先级告警的问题。界面的模式切换只影响查看，实际调度仍由 resolveDay 决定。
