# CueClock 桌面界面

Electron + React。**引擎不在这个进程里**：界面启动时若发现引擎没在运行，会用 Electron 自带的 Node 拉起一个独立的引擎进程（detached）。关掉界面，引擎和日程继续跑；再打开界面会复用同一个引擎。

需要先装好依赖（引擎在 `../engine`，界面在这里）：

```bash
cd app && npm install
# 若 Electron 二进制下载失败（Node 的下载器默认不走代理）：
NODE_USE_ENV_PROXY=1 node node_modules/electron/install.js
```

## 命令

```bash
npm run build                      # 打包引擎 + Electron 主进程/preload + 渲染进程到 dist/
npm start                          # build 后启动桌面应用
npm run typecheck
npm test                           # 开机自启（plist 生成/读写/失效检测）的单元测试
node scripts/make-icons.mjs       # 重新生成托盘/应用图标（assets/，已生成，一般不用跑）

# 不开 Electron，在浏览器里调试界面（需要一个正在运行的引擎）：
cd ../engine && CUECLOCK_HOME=/tmp/cc node src/cli.ts daemon my-project.json
cd ../app && CUECLOCK_HOME=/tmp/cc npx vite     # 打开 http://localhost:5173
```

Electron 启动参数：`--project <文件>`（默认 `<状态目录>/projects/default.cueclock.json`，首次运行自动创建空项目）、`--state-dir <目录>`。
`--daemon-port <端口>`：引擎控制端口（默认 47800）。自检、或本机已有一个引擎在跑时用，避免端口冲突。
自检参数（不需要人操作，打印结果后退出）：
`--smoke-test` 拉起引擎并连接；`--smoke-ui [--screenshot x.png]` 隐藏窗口加载真实界面、点开项目菜单并截图；
`--smoke-app` 新建/切换项目、菜单与托盘、**强杀引擎后自动拉起**、退出并停止引擎。

## 模式主时间轴与目标小时间轴（2026-10-06）

- 每条原有时间线现在是一个**日程模式**，包含一条 24 小时主时间轴和按设备展开的目标小时间轴。旧项目无需迁移，原有组、日期规则、动作和指令引用保持兼容。
- 点模式卡片只切换查看；引擎仍按日期规则和同组优先级自动选择模式。「跟随今日生效模式」会跟随**当前模式所属组**的实际生效结果；并行组可有多个模式同时生效，界面一次展示其中一个。
- 主时间轴显示事件点时刻；目标轴显示该动作**首次发送时刻**，包含前置延时和偏移。引用指令和标签目标会展开到实际设备；重复次数显示在标记上，悬停可看说明。超出当天的发送标红，并由引擎跳过。
- 双击目标轨道新建事件，该目标会成为新动作的默认目标；空事件也会留在对应轨道。新事件先禁用，填写完动作后可勾选「参与调度」。已有动作的实际目标以动作设置为准。
- 多目标事件在各目标轴的标记属于同一事件。拖动任一标记会整体移动该事件的全部动作；目标需要独立移动时，为该目标建立独立事件。选中目标动作后，检查器会定位并高亮对应动作。
- 模式颜色在模式检查器设置；目标颜色可点轨道前的色块，或在设备检查器设置。颜色随项目保存，同一个目标在所有模式中使用同一颜色。
- 支持目标名称/IP/标签筛选、隐藏空轨、收起目标轴、一整天缩放与定位现在。相邻动作分行显示，避免同一时刻的动作遮挡。日志栏可以收起，把空间留给时间轴。
- 可一键创建工作日（含调休上班）/周末/节假日三个互斥模式，也可新建自定义模式或复制整个模式。新建自定义模式和复制的模式默认禁用，配置完成后再启用；复制会重置事件、动作 id，并修正模式对自己的控制引用。
- 项目编辑支持最近 **50 步撤销/重做**，撤销结果仍走原自动保存、校验与冲突处理。Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 或 Ctrl+Y 重做；文本输入框内保留原生文本撤销。切换项目或重新加载不同的项目内容会清空历史，历史不跨应用重启保存。

示例项目：[模式与目标时间轴示例](../engine/data/mode-target-project.json)。从「项目 → 打开」选它即可查看。示例事件全部禁用，目标都是本机回环地址；日历为空，节假日/调休分类以你导入的项目日历为准。

验证：引擎 130 个、桌面端 17 个测试通过，类型检查与构建通过。真实 Electron 的自动化输入事件已验证双击新建、拖动、颜色保存、撤销重做、模式创建复制、筛选、重新加载、项目切换和模板；手动执行新事件后，独立 UDP 回环接收端收到了预期字节。截图检查了 1440px 桌面和 1100px 窄窗口；Windows 和真实设备仍未验证。

## 设备在线检测

设备编辑页「在线检测」：每台设备单独选 **不检测 / Ping / UDP 探测**，检测间隔可选（5 秒到 1 小时，也可自定义）。
- **Ping**：只说明网络层通不通；设备程序死了可能仍能 ping 通，设备屏蔽 ICMP 会误报离线。适合只收不回的设备。
- **UDP 探测**：发一条你选的只读状态查询并校验回包，最准；指令必须开了回包校验。软件不会自动替你选指令。
- 连续失败 3 次判定离线并记告警，恢复时再记一条；侧栏设备下方有状态灯。「立即检测一次」可马上试。

## 编辑锁与备份恢复

- **编辑锁**（设置 →「编辑锁」）：防止别人随手改日程。上锁后只能查看和急停，修改配置、测试发送、切换配置、停止引擎都要先输入密码；界面闲置 10 分钟自动重新上锁；连续输错 5 次锁定 30 秒。**在引擎里强制执行**，重开界面不会绕过。忘记密码：先停引擎，再运行 `node src/cli.ts reset-lock`（在 engine 目录）。
- **备份恢复**（设置 →「配置备份」，或「配置」菜单）：列出自动备份（每次保存前备份旧版本，至少间隔 1 分钟，保留 30 份），选一个恢复。恢复前会先备份当前版本，所以可以撤回。

## 告警（日志区「告警」页签）

回包最终失败、设备连续无回包判离线（及恢复）、休眠唤醒错过事件、触发被拒、网卡缺失/恢复、急停/恢复、调度错误、引擎启动失败，都会作为**告警**记录在日志里（**只记录，不对外发送**）。顶栏的「⚠ N 条新告警」点击进入；页签默认显示需留意的，可切到仅错误或含恢复；显示最近 7 天（来自磁盘日志）。

## 场景库（侧栏「场景」页签）

把要同时做几件事的动作（UDP、指令、延时）配成一个**场景**，时间线和触发器上点「＋ 使用场景」整体引用，可整体后移；场景自成小时间线，内部延时不影响外面的动作。场景编辑页有「立即执行这个场景」（用未保存的草稿也行）。场景里不能再套场景、不能放时间线控制。

## 指令库（侧栏「指令」页签）

每条 UDP 指令配一次：**目标**（设备/标签）、**端口**、网卡（可选）、格式、内容、回包校验、重复、断电恢复。内容里可写 `{{参数名}}`，在「参数」里声明（可带默认值、显示名）。
时间线和触发器上点「＋ 使用指令」，选指令、填参数即可；也可以点「＋ 自定义 UDP」自己设置。引用处可单独覆盖偏移、目标、端口。
指令编辑页有「立即发送这条指令」，用的是正在编辑的内容（即使没保存），并可填参数试发。设备的「默认端口」现在可不填。

## 设置（顶栏「⚙ 设置」）

- **本机网络**（这台电脑的设置，存在引擎的 `settings.json`，**不写进项目文件**——项目拷到别的电脑时网卡 IP 会不同）：
  - 发送网卡：**可多选**，勾选本机的多块网卡（对外 UDP 要发往多个子网时）。发给某个目标时自动用它所在子网的那块网卡；一个都不勾 = 由系统按路由决定。第一个勾选的是「默认」（目标不在任何已选子网时用）。
  - 本地源端口（高级）：可固定，设备回包会回到这个端口，便于防火墙放行；留空则随机。**目标端口在每条指令里设置**，不在这里。
  - 触发器监听：默认只监听所选网卡，可勾选「监听所有网卡」。
  - 点「应用并重启引擎」生效（重启期间约几百毫秒不执行事件）。
  - 所选 IP 本机不存在（网线没插、网卡没起来、地址变了）时，引擎不运行并**每 5 秒自动重试**，网卡恢复后自动启动；顶部有红色提示条和「打开设置」按钮。这对开机自启很重要：开机时网卡常常比软件晚起来。
  - 老项目文件里的 `settings.localAddress/localPort` 仍被识别（没设置过机器级网络时沿用），在设置里点一次「应用」后改用机器级设置。
- **启动与后台**（仅桌面应用）：开机自动启动、关闭窗口后留在托盘/菜单栏。

## 项目、托盘与开机自启

- **项目**：顶栏「项目 ▾」或「文件」菜单：新建（选保存位置，已存在的文件不会被覆盖）、打开、最近项目、在文件夹中显示。切换会先确认（当前日程和触发会停止，约几百毫秒内不执行事件）；目标项目有错误时默认拒绝，可选择仍然打开（引擎不运行）。引擎记住上次打开的项目，下次不带参数启动就用它；文件丢了回退到默认项目并提示。
- **托盘 / 菜单栏**：显示引擎状态和下一事件，可急停/恢复、切换项目、退出。关闭窗口只隐藏（可在设置里关闭此行为）。
- **退出**：「退出界面」只关界面，引擎继续跑；「退出并停止引擎…」会让引擎一起退出。
- **引擎自动拉起**：界面运行期间引擎意外退出，约 3 秒内自动重新拉起（10 分钟内最多 5 次，超过则提示并停止重试）。
- **开机自动启动**：登记的是**界面**（`--hidden` 启动，只在托盘/菜单栏），界面启动时再拉起引擎。macOS 写 `~/Library/LaunchAgents/com.cueclock.app.plist`（登录时运行，不设 KeepAlive，所以「退出界面」后不会被强行拉起）；Windows 用系统登录项（注册表 Run）。不依赖安装包，开发版也能用——此时登记的是本目录的 Electron，目录被移动/删除后会失效，设置里会提示并可「重新登记」。

已知限制：开机自启在 macOS 上验证了 plist 的生成、`plutil` 校验和启停，但**没有真的注销再登录实测**；Windows 完全没测。没有系统级守护——界面和引擎都退出（或界面崩溃后引擎也被杀）时没人重启引擎；开机自启依赖用户登录，现场需要设置自动登录。托盘在 Windows 上未测试。

## 结构

| 位置 | 作用 |
|---|---|
| `electron/main.ts` | 入口：连接引擎、转发事件、窗口、单实例、自检模式 |
| `electron/supervisor.ts` | 拉起引擎（detached）、意外退出后自动重启 |
| `electron/projects.ts` / `menu.ts` / `tray.ts` / `prefs.ts` | 项目对话框与确认、应用菜单、托盘、界面偏好 |
| `electron/preload.ts` | 只向界面暴露 `rpc / onEvent / onConnection`；界面拿不到 Node 和令牌（沙箱 + contextIsolation） |
| `src/transport.ts` | 传输抽象：Electron 走 IPC；浏览器调试走 Vite 开发桥（仅 `vite serve` 时存在，不进生产包） |
| `src/store.ts` | 状态：本地草稿 + 700ms 防抖自动保存 + 冲突/断线重连处理 |
| `src/components/` | 顶栏、设备/触发器侧栏、多轨时间线、检查器、动作编辑器、日志与测试发送 |

## 界面里已有的功能

- 多轨时间线：按组折叠、播放头、毫秒缩放（Ctrl+滚轮）、双击新建、拖动改时间并按设定精度吸附
- 事件点：名称/时间(毫秒)/启用；动作支持 UDP 发送、延时、时间线控制；HEX/ASCII 实时校验与字节预览；目标可选设备或标签；回包校验、断电恢复开关；立即执行、复制、删除
- 时间线与组：互斥/并行、优先级、规则（日子类型、星期、日期范围、指定日期、排除日期）、今日生效原因
- 设备：增删改、标签、测试发送；触发器：来源白名单、口令、匹配、防抖/频率限制、二次确认、动作
- 日历与预览：月历里每格显示当天实际生效的时间线（互斥规则的结果），某组当天没有任何时间线命中会标黄「无日程」；点某天看每条时间线生效/跳过的原因和当天全部执行点（可点进时间线），并可直接把这天设为放假日/调休上班日；「节假日日历…」支持文本批量导入/导出
- 动作「时间线控制」的临时禁用可选「仅今天」（到午夜自动恢复）
- 急停状态在引擎重启后仍保持（顶栏/托盘显示「已急停」，需手动恢复）
- 顶栏：引擎时钟、日子类型、下一事件点倒计时、急停；底栏：TX/RX 日志（ASCII/HEX 切换、筛选、导出）、测试发送、「问题」页签
- 自动保存：校验失败不保存并在「问题」里列出，引擎始终保留最后一个合法版本；多客户端修改冲突时提示
- **草稿保护**：有错误、没能交给引擎的修改会另存一份草稿在本地；关窗口/崩溃后再打开，会提示「恢复草稿 / 丢弃」。修好并保存成功后草稿自动清除。
- 引擎因上次的项目文件丢失而改用默认项目时，顶部有提示条

## 新界面连接旧引擎的兼容性（2026-10-06 黑屏修复）

已确认：仍在后台运行的旧引擎可能返回 `network: {}`，没有新版增加的 `missing` 数组。原界面直接读取 `network.missing.length`，会导致整个 React 页面渲染失败。现由 `src/lib/status.ts` 在状态进入 store 时补齐缺省网卡信息；既支持初次加载，也支持后续状态推送与重连，不修改原始状态或引擎配置。新引擎已有的网卡/缺失信息保持原样，引擎未运行时保持 null。

新增 4 项兼容回归测试；15 项 app 测试、类型检查与构建通过。已直接连接原 PID 97444 / 47800 的旧引擎复现错误，再验证修复后的主界面和设置对话框。实际可见窗口也已截图核对，项目原样保留，引擎未重启。Electron 主进程现在会记录页面渲染错误、加载失败和渲染进程退出，便于排查；启动成功的判断必须包含实际页面渲染，不能只看进程/连接。


## 版本握手、确认重启与错误边界

- 当前功能版本 0.2.0、协议 2；桌面主进程检查运行引擎的版本及源码构建指纹。旧进程可继续保持日程，但界面会明确显示“尚未加载新版修复”，进入查看模式；急停/恢复仍可用，新编辑/项目切换/手动发送需更新引擎。
- 顶部升级提示、设置及错误页都提供「重启引擎…」。点击后由主进程弹出二次确认。取消不停止旧进程；确认才通过认证 shutdown 停止旧服务，并加载当前 bundle。当前项目与实际急停状态会保留；执行中的回包/触发动作可能中断。不会在版本不一致时自动停止正在运行的引擎。
- React ErrorBoundary 包住整个 App，异常时保留未保存草稿并显示可恢复错误页。JS 尚未加载/资源失败时，HTML 初始加载提示也保持可见；视图菜单可重新加载界面。渲染/加载错误写入主进程诊断日志。
- 正则触发器显示捕获参数说明；动态 ASCII/HEX 模板标注为触发时生成，避免把 $N 的 HEX 模板误标为无效字节。
- 时间轴事件名称和时间/待配置提示都限制在各自的分层标签框内，超长内容省略；完整内容保留在悬停说明。
- 17 个 app 单元测试、类型检查与构建通过。真实 Electron 验证了错误页、JS 资源加载失败提示、标签边界，以及隔离引擎的取消/确认重启、准确构建和急停/项目保留。测试脚本和前后失败证据见 .codex-work/20261006-恢复版本触发验收/。
