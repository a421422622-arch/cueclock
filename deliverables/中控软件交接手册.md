## 2. 第一性原理

中控的执行闭环是：计划或手动操作 → 发出指令 → 检查回包与状态 → 显示结果 → 操作员处理异常。

UDP 本身不保证送达或防止重复，所以“已发送”“回包确认”“设备状态回读”分开显示。即便收到普通 OK，也只能按设备协议解释，不能自动推断设备已开机或正在播放。[UDP 标准 RFC 768](https://www.rfc-editor.org/info/rfc768/)

编辑配置与运行配置也分开：编辑先留本机草稿，检查并确认应用后，引擎才采用更新。现场手动接管有期限；期限到后只恢复未来动作，避免重放接管期间已经跳过的指令。

## 4. 操作员日常流程

### 4.1 上班检查

1. 看“运行总览”的连接与自动运行状态；断线时显示的是待核实的缓存信息。
2. 确认“今日生效模式”和日期。时间轴当前查看的模式可能不同，不会因查看而切换运行。
3. 查看下一事件、设备异常、回读更新时间和手动接管期限。未检测或回读未知不能当作在线正常。
4. 检查本地告警。告警只在软件和日志中记录，没有邮件或外部推送。

### 4.2 改日程或设备配置

1. 在模式时间轴或检查器编辑。顶部显示“本机草稿 · 尚未应用”，运行继续使用已应用配置。
2. 点“检查并应用”，逐项查看变化、受影响对象和错误。
3. 有错误返回编辑；不确定可以取消，运行配置不会变。
4. 确认应用：旧配置先备份，运行更新。**旧配置中等待的动作链会取消，已经发出的指令不能撤回。** 暂停和未到期接管保留。
5. 观察后续事件和回读。不要把静态检查通过当成现场设备执行成功。

操作面板的“操作”模式使用已应用配置，“编辑”模式使用草稿。草稿未应用时，事件点立即执行和面板试按禁用，避免显示草稿却执行旧配置。指令/场景检查器的草稿立即试发是显式手动操作，会真实发包。

### 4.3 临时手动控制

1. 总览选择接管期限，再点某台设备“接管设备”；或给面板按钮配置“手动接管”秒数，使操作时接管全部目标。
2. 按面板按钮或拖滑块。自动日程、触发、恢复及自动重试不会覆盖被接管设备；其他设备继续自动运行。
3. 检查实际回读。面板亮灭/数值是最后操作记录，不是实际设备状态。
4. 完成后“交回自动”，或等期限到。交回时不补发接管期间跳过的动作。

仅手动按按钮、但未设置接管，不会自动停掉日程。开/关动作建议使用明确的 ON / OFF 语义，避免把可重复的状态指令与翻转指令混用。

### 4.4 暂停、退出和取消场景

- “暂停自动日程”暂停自动日程与 UDP 触发，手动面板仍可用；恢复不会补发暂停期间错过的事件。它不是切断设备电源的硬件急停。
- 总览的场景卡可二次确认“停止后续步骤”；已发送的内容不能撤回。
- 关闭窗口并保留菜单栏：界面仍在后台，现有引擎监督继续运行。
- “退出界面”：引擎继续运行，但界面监督结束；可选登录守护尊重正常退出，不会强制拉起。无人值守时使用关闭窗口留后台。
- “退出并停止引擎”：需确认，之后自动任务停止。

## 5. 状态回读、场景和滑块配置

### 5.1 区分三类状态

| 显示 | 能说明什么 |
|---|---|
| Ping 可达 | 网络层有响应，不代表设备应用正常 |
| UDP 探测 / 回包确认 | 所选指令得到符合匹配规则的回包，意义取决于协议 |
| 已发送 · 未校验回包 | 软件发出了内容，设备是否执行未知 |
| 发送 / 等待回包 | 操作正在处理，尚未得到最终结果 |
| 回读字段 | 设备最近一次符合解析规则的状态报告，附更新时间 |
| 过期回读 | 超过保鲜期限，或之后发过新的控制指令，不能当作当前状态 |
| 面板亮灭 / 数值 | 最后操作记录，不能替代回读 |

设备检查器开启“设备状态回读”，选择 ASCII 或 HEX，填状态正则、字段捕获组和过期时间。ASCII 按字节解码并去掉末尾 CR/LF；HEX 正则匹配大写连续十六进制。状态回包最大解析 4096 字节，最多 16 个字段，捕获文本只展示，不参与指令执行。

测试示例：回包 `POWER=ON LEVEL=128`，正则 `^POWER=(ON|OFF) LEVEL=(\d+)$`，字段 `电源=1` 与 `亮度=2`。此示例只用于本机模拟；现场必须使用厂家协议，并选择明确的只读查询作为在线探测。

### 5.2 场景执行

- 默认“按时间”：偏移和延时保持原有日程语义，回包可并行等待。
- “按顺序”：按照列表逐步等待发送或回包结果；延时/偏移从前一步完成后开始算。没有回包配置时只等待发出，不能确认设备就绪。
- 失败策略默认“停止后续”；可选“继续后续”，整体仍保留失败结果。禁用或跳过也不伪装成功。
- 顺序场景每步时刻取决于前一步结果，静态时间轴的内部偏移仅作示意，实际以总览进度和 TX 日志为准。
- 进度中的“动作处理完成”不是设备状态确认。“启动前未观察”也不会补成成功。
- 顺序场景禁止自动断电补发/chase。中途重启后先查询设备，操作员再决定是否重跑。按时间的场景仍保留尚未到点偏移动作与既有 chase 行为。
- 场景进度是当前引擎内存记录，返回最近 20 条；更早或重启前的执行痕迹查看日志。

### 5.3 滑块映射

界面范围 0–100，单位 `%`，启用映射，设备范围 0–255，小数位 0。动作 ASCII 可用 `{{value}}`，HEX 使用 `{{hex}}`；指令参数也可代入。

先按界面步长吸附，再线性映射，最后取指定精度。50% → 128 → HEX `80`。可反向范围；HEX 输出必须非负整数。没有 mapping 的旧项目继续发送原始值，不会自动转换。初始位置只显示，不发送。

## 7. 风险和异常处理

| 情况 | 处理 |
|---|---|
| 设备显示未知 | 配置检测/只读状态查询，核对 IP、端口、网卡与协议 |
| 已发送但无效果 | 查询实际状态；核对字节与结束符。重发前确认指令能安全重复 |
| 回包超时/不符 | 查看日志的目标与字节、超时、重试；普通 OK 与实际状态可能不同 |
| 旧回读过期 | 获取新回读；不要依据旧值反复翻转开关 |
| 本机草稿冲突 | 保留草稿并检查运行配置；预览必须重新生成，不要强行覆盖 |
| 引擎重启后旧预览失效 | 重新检查并应用，旧实例的预览不能提交 |
| 机器设置保存失败 | 查看本地告警。暂停会立即生效，但持久化失败时不要假设重启会保持新状态；接管/面板也会明确报告保存失败 |
| 界面错误页 | 草稿保护后重载；核对引擎版本与能力，在日程空档由操作者确认更新 |
| 电脑休眠/时间跳变 | 检查错过事件与恢复日志，核对设备当前状态；不要依靠休眠期间准点发送 |
| 自动拉起反复失败 | 界面监督有频率限制，查看 `daemon.out.log`；系统守护需有效路径和登录环境 |

Mac 防休眠只防止空闲系统休眠，不保证合盖、手动休眠或断电。登录守护不是开机即运行的系统服务，仍依赖用户登录和有效程序路径。需要在部署路径上单独验收，不要从临时构建的成功推断本机登录项一定可用。

- 新功能必须更新能力声明，行为不兼容时更新功能版本；不能只看 PROTOCOL_VERSION。仅构建不同仍允许同功能/能力的既有操作，但要提示修复未加载。
- 应用使用预览中的配置快照、baseRev 和 instanceId；不使用后来又变动的草稿偷偷替换预览内容。
- 设备普通发送/ACK 不伪装成实际状态；控制后的旧回读过期，晚到旧回包不能盖掉较新的控制记录。
- 接管目标必须展开场景与指令、包含标签设备；后台检测不属于控制操作。
- 自动恢复、自动重试和顺序场景后续步骤必须尊重接管、暂停、取消、停止和配置更新。
- 机器设置写入排队、先写临时文件再原子替换；暂停先立即生效，恢复在持久化成功后执行。
- 不启用手机网页访问或告警外发；安装包仍暂缓。

### 11.2 复核发现并已修复的问题

**面板按钮在“机器设置落盘失败”时被报成“执行失败”，但指令其实已发出。**

- 复现：状态目录只读后按开关，外部设备确实收到 `OFF`，界面却显示“执行失败：机器设置保存失败”。操作员很可能再按一次，把开关翻回去。磁盘满、权限变化时会发生。
- 修复：`runPadTile` 在指令已发出、状态已切换后，落盘失败只返回 `persistFailed: true`；界面提示“已执行，但状态没能保存到磁盘：重启引擎后亮灭可能不对”。滑块同理。先写了会失败的测试（`settings-atomic.test.ts`），修后引擎 226/226、界面 63/63、类型检查通过。
- **没改的**：暂停（先生效再报持久化失败）与手动接管（报保存失败）保持原设计；这两处报错的措辞本来就是“保存失败”，不会被误读成动作没发出。

### 11.3 需要你知道的风险

1. **用户机器上的 47800 引擎仍是 0.2.0（现在代码已是 0.4.0）。** 新界面会判定它“功能版本不兼容”，此时**禁止编辑和保存**（只读和暂停仍可用），也没有总览、接管、回读等新功能，直到按第 8 节重启引擎。这是设计，不是故障；但要在日程空档做，别在现场开场前才发现。
2. **登录守护在 `~/Documents/…` 路径下没能完成初始化（手册第 3.4 节），原因未确认。** 我的判断（**未验证**）：macOS 对“文档”文件夹有隐私保护，由 launchd 拉起的进程可能没有读取权限。验证办法：把构建好的程序副本放到非保护目录（如 `~/CueClock-run/`，不要放在 Documents / Desktop / Downloads），在那里重复一次“强杀界面→自动拉起”的 launchd 测试；如果通过，正式部署就不要放在 Documents 里。
3. **回退要谨慎。** 新版配置多了 `feedback`、`mapping`、`takeoverSec`、`execution` 等字段。旧版是否会在保存时丢掉这些字段我**没有验证**；回退前先导出一份配置，回退后在旧版里不要保存配置，除非先确认。
4. 草稿/应用分离后，**忘记点“检查并应用”就等于改动没有生效**。界面顶部有“本机草稿 · 尚未应用”和“检查并应用”，培训时要强调；关窗口前草稿保存在本机浏览器存储里，换电脑不会带走。
5. 手册里的 `npm start` 会先重新构建再启动，约半分钟；现场升级时留够时间。
