# 节假日日历覆盖调查

调查日期：2026-10-07。本轮只读代码、样例及正式项目文件，并运行纯函数探针；没有改写项目、修改日历规则、更新正式引擎或登录守护。

## 结论

存在漏录风险，但不是“年度表到期后被清空”。软件不内置完整官方年度表，不联网更新；**任何没有录入的日期都立即按星期回退成普通工作日或周末**。跨年时未录入下一年的放假、调休日期，就继续按这个规则选择模式，没有专门的到期告警。

## 第一性原理

软件必须知道某一天的日子类型，才能命中工作日、周末、节假日或调休上班模式。星期几可以计算，年度放假及调休安排需要明确数据。空数据既可能表示没有特殊安排，也可能表示尚未录入；现有模型不能区别这两种情况。

## 事实与假设

- `engine/src/calendar.ts:dayKind` 按放假日期、调休上班日期、星期依次判断。日期不在前两张表，就只看星期。
- `CalendarData` 只有 `holidays` 与 `makeupWorkdays`，没有来源、已核对年份、有效期或完整性标记。最后一条日期不能证明全年已录齐。
- 项目创建与规整不会补年度表；实际日程规则通过 `rules.ts` 使用同一个 `dayKind`。UI日历编辑说明明确要求按官方通知手工填写，文本导入“应用”会整体替换两张表，而不是合并。所以只粘贴下一年可能覆盖原年份数据；多年的日期可以同时录入。
- `engine/data/sample-project.json` 只有7个示例放假日、2个示例调休日，注明不是官方安排；`mode-target-project.json` 日历为空。它们都不能当作生产年度表。
- 官方2026安排由国务院办公厅于2025-11-04公布；2026-01-01放假、01-04上班、09-20上班、09-27处于中秋假期。[国务院办公厅通知，北京市政府转载](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)

纯函数探针用仓库示例数据，并设置四个互斥模式，结果如下；“选中模式”证明影响会到达模式选择，而不只是日历颜色。

| 日期 | 示例数据下的分类与选中模式 | 对照/解释 |
|---|---|---|
| 2026-01-01 | 普通工作日 | 示例没录此日期；官方安排为放假 |
| 2026-01-04 | 普通周末 | 示例没录调休；官方安排为上班 |
| 2026-09-20 | 普通周末 | 示例没录调休；官方安排为上班 |
| 2026-09-27 | 调休上班日 | 示例刻意非官方；官方安排为中秋放假 |
| 2026-10-01 | 法定节假日 | 示例有这一条，分类命中 |
| 2026-10-10 | 调休上班日 | 示例有这一条，分类命中 |
| 2026-12-31 | 普通工作日 | 没有跨年预警或年度覆盖检查 |
| 2027-01-01 | 普通工作日 | 下一年未录，仍按星期计算 |
| 2027-01-02 | 普通周末 | 同上 |

同一探针在内存里导入**假设**的2027-01-01放假和2027-01-02上班后，分别分类为节假日与调休上班日。说明解析器支持跨年数据，缺口在覆盖确认与提醒。这两条只用于探针，不代表2027官方安排，本轮不判断2027正式通知是否发布。

只读正式项目快照：没有calendar字段；有1条时间线和1个禁用事件，未使用dayKinds规则。因此不能由本次调查推断现场已经误执行；正式配置可能随后由用户修改，此处只是调查时的快照。

## 反方与风险

按星期回退适用于不依赖法定假日的场所；不应因年度数据缺失而擅自暂停全部日程。反过来，使用节假日/调休模式的场所，漏录可能选错模式。仅按“最后日期的年份”推断已覆盖，会让一张只录了国庆的表假装覆盖全年。
